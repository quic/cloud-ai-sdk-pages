.. _reference-to-checklist:

Checklist
=========

Installation Checklist
----------------------

First, check :ref:`Hardware requirements <reference-to-hardware-requirements>` and :ref:`supported operating
environments <reference-to-Supported-Operating-Systems>`.

Local Server Installation
--------------------------

1. Set up Linux server/workstation environment
   (:ref:`Pre-requisites <reference-to-pre-requisites>`)

   -  Enable 32 message signaled interrupts (MSI) in UEFI/BIOS setup
      (:ref:`MSI
      instructions <reference-to-msi>`)

2. Install Platform and Apps SDKs (:ref:`Cloud AI
   SDK <reference-to-cloud-ai-sdk>`)

3. **Tip:** To run Platform SDK tools without superuser (sudo)
   privilege, add yourself to the qaic group.

   ::

       sudo usermod -aG qaic $USER

   -  Log in again for the changes to take effect, or run 'newgrp qaic'.

.. _reference-to-card-health-function:

Verify Card Health/Function
----------------------------

1. Check PCIe enumeration:

   ::

       $ lspci | grep Qualcomm
       01:00.0 Unassigned class [ff00]: Qualcomm Device a100

   -  A PCIe enumeration failure may indicate an unsecure connection.
      Try re-inserting the card, or troubleshoot with a different PCIe
      card.

2. Check device nodes:

   ::

       ls /dev/mhi*
       /dev/mhi0_QAIC_DIAG /dev/mhi0_QAIC_QDSS /dev/mhi1_QAIC_DIAG /dev/mhi1_QAIC_QDSS

   -  For every card, QAIC_DIAG and QAIC_QDSS nodes are created.
   -  If mhi\* folders do not exist, double-check the :ref:`MSI
      settings <reference-to-msi>`
      in UEFI/BIOS setup

3. Check card health and status with :doc:`qaic-util <../../../System-Management/system-management/index>`

   ::

       sudo /opt/qti-aic/tools/qaic-util -q | grep -e Status -e QID

       QID 0
         Status:Ready
       QID 1
         Status:Ready
       QID 2
         Status:Ready
       QID 3
         Status:Ready

   -  'Status: Ready' indicates card(s) is in good health. Shown here
      are a system with 4 Cloud AI SoCs (Each card may have one or more
      SoCs based on the SKU).
   -  'Status: Error' indicates the respective card(s) has not booted up
      completely.
   -  Card could still be booting. Wait for a few mins and retry above
      command.
   -  Card error could be due to several reasons - unsupported
      OS/Platform, secure boot etc.

4. Run a test inference workload with qaic-runner CLI to sanity check
   HW/SW function. Example:

   ::

       sudo /opt/qti-aic/exec/qaic-runner -t /opt/qti-aic/test-data/aic100/v2/1nsp/1nsp-conv-hmx/ -a 14 -n 5000 -d 0

       Input file: /opt/qti-aic/test-data/aic100/v2/1nsp/1nsp-conv-hmx//user_idx0_in.bin
       ---- Stats ----
       InferenceCnt 5000 TotalDuration 15094us BatchSize 1 Inf/Sec 331257.453

   -  ``-d`` specify QID to run the workload on.
   -  ``-a`` edit value based on no of NSPs in specified QID.

A positive Inf/Sec indicates HW/SW is functioning correctly. The Inf/Sec
reported depends on ``-a`` specified in the command.

Virtual Machine Setup
----------------------

1. Configure PCIe pass-through for the supported
   :ref:`Hypervisor <reference-to-hypervisors>`
2. Configure :ref:`message signaled
   interrupts <reference-to-msi>`
   in UEFI/BIOS setup and :ref:`Hypervisor <reference-to-hypervisors>`
3. Install and configure :ref:`Hypervisor <reference-to-hypervisors>`
4. Configure and launch Virtual Machine instance with one of the
   supported :ref:`Operating
   Systems <reference-to-Supported-Operating-Systems>`
   and :ref:`Pre-requisites <reference-to-pre-requisites>`
5. Install :ref:`Cloud AI SDKs <reference-to-cloud-ai-sdk>`
6. Check :ref:`Card Health/Function <reference-to-card-health-function>`

Docker Setup
-------------

1. Install Platform SDK on host system or virtual machine (:ref:`Cloud AI
   SDK <reference-to-cloud-ai-sdk>`)
2. Build Docker image and start the container
   (:ref:`Docker <reference-to-docker>`)
